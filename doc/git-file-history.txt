*git-file-history.nvim*                 Current-file Git history diff for Neovim

==============================================================================
INTRODUCTION                                            *git-file-history*

GitFileHistory opens a two-pane file-history workbench. By default HISTORY is
on the left and the real editable CURRENT buffer is on the right:

        HISTORY  ->  CURRENT

CURRENT is never replaced by a Git snapshot. HISTORY is read-only and can move
older/newer through commits that touched the file. Unsaved CURRENT changes are
included in the comparison.

Both panes use |diff-mode| but unchanged regions remain fully expanded by
default. Visible transfer arrows identify historical diff hunks that can be
pulled into CURRENT.

==============================================================================
COMMANDS                                        *git-file-history-commands*

:GitFileHistory             Open history for the current file.
:GitFileHistoryOlder        Move HISTORY one revision older.
:GitFileHistoryNewer        Move HISTORY one revision newer.
:GitFileHistorySelect       Select a revision through |vim.ui.select()|.
:GitFileHistoryRefresh      Re-read the file history from Git.
:GitFileHistorySwap         Swap CURRENT/HISTORY window positions.
:GitFileHistoryApplyHunk    Pull HISTORY hunk at cursor into CURRENT.
:GitFileHistoryApplyFile    Restore whole selected revision to CURRENT.
:GitFileHistoryClose        Close comparison and restore CURRENT options.

==============================================================================
DEFAULT MAPPINGS                                *git-file-history-mappings*

Mappings exist in the historical scratch buffer.

[g          older file revision
]g          newer file revision
H           older file revision
L           newer file revision
s           select revision
r           refresh Git history
p           pull HISTORY diff hunk under cursor into CURRENT
<CR>        same as p
Visual p    pull selected HISTORY diff range into CURRENT
P           restore complete selected HISTORY revision into CURRENT
x           swap CURRENT/HISTORY sides
q           close

Native diff mappings remain available, especially:
]c          next diff hunk
[c          previous diff hunk

==============================================================================
HUNK ACTIONS                                *git-file-history-hunk-actions*

When HISTORY is on the left, each diff hunk receives a right-aligned transfer
marker pointing toward CURRENT:

        HISTORY                 CURRENT
        old block          ->   new block

Put the HISTORY cursor in that hunk and press p or <CR>. Only that diff hunk is
applied to the real CURRENT buffer.

After :GitFileHistorySwap the direction reverses and HISTORY displays a left
pointing marker toward CURRENT.

The markers are recalculated after CURRENT changes and after HISTORY moves to
a different revision.

==============================================================================
RESTORING HISTORY                               *git-file-history-restore*

The HISTORY buffer is always read-only. Restore operations modify only the real
CURRENT buffer and therefore participate in normal Neovim undo.

p / <CR>
        Pull the diff hunk under the HISTORY cursor into CURRENT.

Visual p
        Pull only the selected HISTORY diff range into CURRENT.

P
        Pull the complete selected historical file into CURRENT. Internally
        this uses the complete |:diffput| range, including deleted lines.

After each restore the diff is recalculated and both panes remain expanded.
Use |u| in CURRENT to undo a restore.

==============================================================================
CONFIGURATION                                  *git-file-history-config*

Default layout:

        current_side = "right"

Set current_side = "left" to start with CURRENT on the left instead. The x
mapping can swap either layout at runtime.

Diff folding is disabled by default:

        fold_unchanged = false

Hunk transfer markers can be disabled with:

        hunk_actions = false

The default indicators are:

        hunk_indicators = { right = "→", left = "←" }
